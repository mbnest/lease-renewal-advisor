# Lease renewal decision agent

Status: architecture phase. Designed, not built. Last updated 2026-10-02.

## Problem
- Single-family rental operators make thousands of lease renewal decisions a year
- Inputs are scattered across market data, maintenance history, payment history, and resident messages
- Pricing a renewal too high drives costly turnover. Pricing too low leaves revenue on the table

## Approach
- A multi-agent system reviews each lease expiring in the next 90 days
- Specialist agents each own one data domain: condition, market, and resident
- A supervisor combines their findings into a recommendation: renew or not, a suggested rent change, key risks, and a draft resident message
- A critic agent challenges unsupported claims and blocks prohibited reasoning
- Code enforces policy: rent clamp, arbitration, and gate states
- Output is advisory. A human approves every rent change and resident message

## Data and evaluation
- All data is synthetic, generated by code with planted, known-cause scenarios
- Every recommendation is graded against an answer key
- Results are compared against a single-agent baseline
